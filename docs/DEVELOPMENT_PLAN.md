### 운영 전제 (배포 전까지)

- 수집은 개발 PC에서 WSL Airflow + E: USB가 연결된 동안만 실행되면 된다. PC·WSL·USB가 꺼진 동안의 기사는 피드 보관 범위(예: SBS 약 5시간 40분) 밖이면 수집되지 않는다.
- 배포는 무료 플랜으로 팀원 각자 개인 사용 목적으로 한다. 무료 플랜의 메모리·상시 실행 제한에서 Airflow 운영이 가능한지는 10단계에서 **확인 필요**.

## 기능 간 의존 관계

- 모든 DB 기능 → TiDB `.env` 설정 + Alembic 마이그레이션 적용
- 뉴스 조회 API·React 뉴스 화면 → `news_articles` 테이블 및 수집 데이터
- 번역(4) → 해외 출처 수집(3). 분류(5)·이슈 묶기(6)는 번역된 한국어 기준
- 분류(5) → 충분한 누적 기사(2·3)
- TOP 10(8) → 분류(5), 이슈 묶기(6), SNS 언급량(7)
- Airflow DAG(예정) → `pipelines/jobs`의 수집 작업 (API 코드와 분리, 별도 Python 환경)
- React 데모 화면 → 각 모듈 API 구현 후 실제 연결
- 모듈 간 데이터 교환 → 통합 전 팀 협의 (미정)
